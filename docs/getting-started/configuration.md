# Configuration

## `polyglot.toml`

`polyglot.toml` is the project configuration file. It is read when you build a directory that contains one: `polyglot build` (current directory) or `polyglot build path/to/project`.

A minimal project, as generated by `polyglot init`:

```toml
[project]
name = "demo"
version = "0.1.0"

[target]
triple = "x86_64-unknown-linux-gnu"
opt_level = 2

[plugins]
rustc = "0.1"

[[bin]]
name = "demo"
source = "src/main.c"
```

## Keys the Driver Honors

| Section | Key | Effect |
|---------|-----|--------|
| `[[bin]]` | `name` | output executable name for the project build |
| `[[bin]]` | `source` | the source file compiled (first `[[bin]]` wins) |
| `[language]` | `rust = true` | build `src/main.rs` with `rustc` instead of invoking a C/C++ compiler |
| `[compiler]` | `cc` | compiler executable for C sources (name or absolute path) |
| `[compiler]` | `cxx` | compiler executable for C++ sources |

Everything else the `init` template writes (`[project]` metadata, `[target] triple`/`opt_level`, `[plugins]`, and per-bin `cflags`/`ldflags`) is reserved for future releases: accepted, but not yet honored when building. Optimization level and target come from the command line instead (`polyglot --opt-level aggressive --target ... build`).

Without `[[bin]] source`, a project build falls back to the first `src/*.c` / `src/*.cpp` file it finds.

## Compiler Selection: `[compiler]`

Use `[compiler]` to pin the toolchain for a project (cross builds, a vendored toolchain):

```toml
[compiler]
cc = "/opt/llvm-17/bin/clang"
cxx = "/opt/llvm-17/bin/clang++"
```

Values may be absolute paths, paths relative to your `PATH`, or plain command names. If a value does not resolve to an executable, the build fails with:

```text
error: polyglot.toml [compiler] cc = '/nonexistent/cc' does not resolve to an executable
```

`POLYGLOT_CC` / `POLYGLOT_CXX` environment variables take absolute precedence over `[compiler]`.

## Rust Projects

`polyglot init hello --language rust` scaffolds:

```toml
[project]
name = "hello"
version = "0.1.0"

[language]
rust = true

[target]
triple = "x86_64-unknown-linux-gnu"
opt_level = 2

[[bin]]
name = "hello"
source = "src/main.rs"
```

with a sample `src/main.rs`. `polyglot build` in that directory invokes `rustc` (discovered like any other tool; `doctor` reports it) with the matching optimization level and links `src/main.rs` to the `[[bin]]` name.

## Precedence

1. `POLYGLOT_CC` / `POLYGLOT_CXX` environment variables (highest)
2. `polyglot.toml` `[compiler] cc` / `cxx`
3. Toolchain auto-discovery: `--compiler` > `PATH` > scan directories (lowest)

CLI flags (`--opt-level`, `--target`, `-o`, compile flags) are not configurable via TOML. They are CLI-only.

## Validation

```bash
polyglot build   # reports parse errors, missing sources, bad [compiler] values
```

Common errors: malformed TOML (with a warning), `Source file not found`, `No source file found in project`, and unresolvable `[compiler]` values.
